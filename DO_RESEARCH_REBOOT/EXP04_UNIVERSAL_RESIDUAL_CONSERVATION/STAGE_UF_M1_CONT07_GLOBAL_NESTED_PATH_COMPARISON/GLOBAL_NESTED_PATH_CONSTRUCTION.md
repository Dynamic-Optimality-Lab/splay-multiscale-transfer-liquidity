## Why the two side words are still separate

Their union need not be monotone. Moreover an inside-only merged shadow can see an SS old-parent pairing where the original sees an opposite pairing because outside accesses were omitted. It then imports exterior keys into the other child and can lose the next original old-g match. The complete11-key protected counterexample proves this even with original U/Pi blindness and an unacquired U opposite creator. It is shallow and has no R6/C_old gap, so it does NOT refute MERGE0 restricted to canonical C_old paths. It refutes using PF geometry/U alone to justify that merger.

A precise valid conditional replacement: as long as the merged FULL g component is coupled, a retained hit preserves it unless g is a non-target old parent in an SS SHADOW double. This is the exact first contamination mechanism. Preventing it still does not make the mixed two-side word a monotone sequential scan. The proven envelope uses separate sides.
